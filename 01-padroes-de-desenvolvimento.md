# Padrões de Desenvolvimento do Noronha Studio

## Princípios
- Preferir a solução mais simples que cumpra os requisitos.
- Separar interface, lógica de negócio e acesso a dados.
- Usar nomes claros e consistentes.
- Evitar duplicação desnecessária.
- Validar entradas no cliente e no servidor.
- Não confiar em dados enviados pelo navegador.
- Manter segredos fora do código e do repositório.
- Usar controle de versão Git.
- Documentar decisões que afetem arquitetura ou manutenção.

## Processo de implementação
1. Confirmar requisitos e critérios de aceite.
2. Identificar riscos e dados envolvidos.
3. Propor estrutura de pastas e tecnologias.
4. Implementar uma parte pequena e testável.
5. Executar testes e verificar erros.
6. Revisar segurança, acessibilidade e responsividade.
7. Atualizar README e instruções de execução.
8. Registrar o que foi alterado e o que ainda falta.

## Regra para respostas da Noronha AI
Quando o usuário pedir uma alteração de código, fornecer o arquivo completo atualizado quando isso for viável, não apenas um fragmento isolado. Informar o caminho do arquivo e os passos para testar.

## Antes de adicionar uma biblioteca
- Verificar se é necessária.
- Conferir manutenção, licença e compatibilidade.
- Evitar dependências abandonadas ou excessivas.
- Não instalar ou executar código de procedência desconhecida sem revisão.
